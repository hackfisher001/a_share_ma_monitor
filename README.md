# A股 30 日均线监控助手

监控 `watchlist.yaml` 里的 A 股、美股与 ETF。默认进入“行动模式”：只有**盘中急跌**这类你还能当场下单的信号才即时推送；MA30、回撤和短期涨跌压缩进日报，避免让飞书变成 K 线连续剧。

可用 **GitHub Actions** 定时跑，也可部署到 **阿里云轻量/ECS** 用 crontab 跑（推荐长期方案）。

## 1. 配置飞书机器人（约 1 分钟）

1. 打开（或新建）一个飞书群  
2. 群设置 → **群机器人** → **添加机器人** → 选 **自定义机器人**  
3. 名称随意，例如 `MA30监控`；安全设置建议选「自定义关键词」，关键词填 `买入` 或 `MA30`（消息里已包含）  
4. 复制 Webhook 地址  

本地：

```bash
cp .env.example .env
# 把 FEISHU_WEBHOOK_URL= 后面换成你的地址
```

连通测试：

```bash
python -m src.main --notify-test
```

手机飞书应立刻收到「连通测试」卡片。

## 2. 快速开始

公司 VPN 下 PyPI / 行情源常不稳定，建议用国内镜像；正式长期跑推荐阿里云国内机。

```bash
cd a_share_ma_monitor
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
cp .env.example .env   # 填入 FEISHU_WEBHOOK_URL
# 编辑 watchlist.yaml：改成你要盯的股票

python -m src.main --notify-test   # 测飞书
python -m src.main --dry-run       # 只算信号，不推送
python -m src.main                 # 正式推送
```

## 推送的几类消息

| 类型 | 触发 | 定位 |
|---|---|---|
| 急跌提醒 · -N% | 实时价对比**昨收**跌破该标的的 σ 校准档位 | **即时**，盘中就推 |
| 近期异常回撤 | 跌幅落在该标的自身近一年最差 `recent_pullback_percentile`% | **即时**，盘中就推 |
| 走势提示 · MA30 | 现价距 MA30 在 ±`touch_pct` 以内 | 被 `action_only` 静音 |
| 回撤观察 · N% | 距 252 日高点跨过 `drawdown_levels` 的某一档 | 被 `action_only` 静音 |
| 收息仓 · 股息率 | 随日报 | 收息仓的绝对估值锚 + 分红被砍监控 |
| 持仓与成本 | 随日报 | 由 `trades.csv` 回放出的真实浮盈 |
| 每日巡检心跳 | 每天固定一条 | 用来判断监控本身是否还活着 |

`notifications.action_only: true` 是默认值。**急跌提醒和近期异常回撤不受它影响**——这两类只在你还能下单时有价值，压进收盘后的日报等于扔掉。

被静音的两类**仍然会记录已跨过的档位**。否则把 `action_only` 改成 `false` 的那一刻，所有历史档位会一次性重放——一只已跌 22% 的标的立刻推 5/10/15/20 四条。

### 盘中每只单独一张卡

同一轮巡检触发多只时，**每只各自发一张卡**，末尾附近一年走势图（和日报里的 sparkline 同款）。这样扫一眼就能区分「涨到高位后急跌」还是「横盘后急跌」。

同一只标的同时跨过 2σ/3σ/4σ 时只发最深那档，但各档去重状态都落库，当天不会重复触发。多只之间按 σ 倍数决定发送顺序（更反常的先发），不按跌幅大小。

### 急跌提醒

用实时价对比昨收，每次巡检都判一次，所以开盘跳空或盘中跳水都能当场收到。每档每天最多推一次，次日重置。

**档位按标的自身波动率换算，不用全表统一的固定百分比。** 固定 -3% 在这份清单上是失效的——实测近 250 日：

| 标的 | 日σ | -3% 相当于 | 年内触发 ≤-3% |
|---|---:|---:|---:|
| 长江电力 | 0.86% | −3.5σ | 0 次 |
| 招商银行 | 1.09% | −2.8σ | 1 次 |
| 紫金矿业 | 2.99% | −1.0σ | 29 次 |
| AMD | 4.52% | −0.7σ | 47 次 |
| 美光 | 5.15% | −0.6σ | 48 次 |

同一个数字对长江电力是一年都碰不到的极端事件，对美光是每五个交易日一次的日常噪音。全组合按固定档一年触发约 257 次（平均每个交易日一次以上），其中 85% 来自 6 只高波动标的。按 σ 定档后，各标的「被提醒的稀有度」才可比。

`sigma_levels: [2, 3, 4]` 换算出来大致是：长江电力 -1.7/-2.6/-3.4%、纳指100ETF -2.5/-3.7/-4.9%、英伟达 -4.8/-7.2/-9.6%、美光 -10.3/-15.4/-20%。想更灵敏就调小（改 1.5 大约让提醒量翻三倍）。

历史不足 60 根时算不出 σ，自动回落到 `levels` 的固定档（清单里的 `SPCX` 就是这种，2026-06-12 才上市）。个别标的可用 `dip_levels: [5, 8]` 手工覆盖。

它刻意不做「是否属于该标的历史极端」的分位过滤：原先的 3 日 / 20 日分位阈值是为慢跌设计的，实测中黄金 ETF 单日跌 2.37% 两个条件都不满足，正是这类跳空被漏掉。

A 股与美股都支持盘中（美股行情走腾讯美股板）。`GC=F`、`BTC-USD` 这类非普通代码取不到实时价，会回退到最近收盘价，消息里会标注。

### 归因：是大盘在跌，还是它自己在跌

每条提醒都会附上同市场基准（A 股 → 沪深300ETF，美股 → 纳指100ETF）的当日涨跌和**超额跌幅**。基准本来就在监控清单里，不产生额外请求。

超额按 **beta 调整**后再算。直接减指数会把每只高 beta 标的都判成有消息面：AMD、美光的 β≈2，大盘 -3% 时它们跌 -7% 只是 beta，不是新闻。

是否算「个股独有」则按该标的**自身的残差 σ**判断（≥2× 常态残差，且绝对值 ≥1%），同样不用固定百分比——美光的常态残差本就比长江电力大好几倍，一个统一的百分比会重复固定档位犯过的错。

### 近期异常回撤

和「急跌提醒」的固定档位不同，这一类问的是**「这个跌幅对这只票来说正不正常」**：近 3 日跌幅或距 20 日高点，落在该标的自身近一年分布的最差 10%。低波动的长江电力跌 5% 可能就很异常，高波动的紫金跌 5% 只是日常，固定阈值分不出这个差别。

它同样是盘中实时的。日线行情源会把当日在进行中的一根按实时价接上，所以下跌当天就能收到，不必等收盘。

重复提醒的规则不是简单的冷却：

- 距上次提醒**再跌 3%** → 立刻重提，并标注「较上次提醒（32.43）又跌 4.4%」
- 否则挂满 `recent_pullback_cooldown_days`（7 天）才会再提

只用平铺冷却是不够的：信号可能在一次当天就收回去的浅跌上触发，然后把接下来一周真正的深跌全部静音——恰好是最该出声的时候。

### 走势提示与回撤观察

这两类**只回答「现在贵还是便宜」**，不代表该推迟买入。两份回测都指向同一个结论：

- **定期现金流**（`docs/定投与做T回测.md`，12.3 年、含 2015/2018/2022 三轮下跌）：「攒钱等回撤」在 13 个标的上 **0 胜**，等 -10% 平均每年少赚 1.71%，等 -20% 少赚 3.56%。
- **一次性资金**（`docs/一次性资金入场时点回测.md`，遍历 2205 个入场日）：等 -10% 的胜率只有 **27%**，四次里三次不如立刻买。原因是回撤按**移动的高点**算——等待期间价格上涨，触发 -10% 时往往仍高于当初放弃的入场价。而且一年内等不到 -20% 的概率高达 33%（纳指ETF）到 85%（黄金ETF）。

结论：**到账就买。** 年终奖这类一次性大额可分 3 个月买完（平均少赚约 1.5%，换取不押在单一点位），但不要等回撤。

### 收息仓 · 股息率

招行、中国移动、宁沪高速、长江电力、中国神华在 `watchlist.yaml` 里标了 `income: true`。对它们来说收益的很大一部分来自分红，而「距一年高点」只看价格，既低估真实回报也说不清贵贱。跌 10% 但股息率 6% 和跌 10% 但股息率 3% 是完全不同的两件事。

更重要的是**分红被砍是收息股唯一该让你重新考虑持有的信号**，价格类指标完全看不到它。同比跌破 -20% 会在日报里标出来。

口径是**最近一个完整财报年度**的现金分红，按 `报告期` 归集。这一点不能简化，有两个真实的坑：

- **不能比较单笔**：招行 FY2024 一次派 2.000 元/股，FY2025 拆成中期 1.013 + 年度 1.003。单看最后一笔像腰斩，按年度合计 2.016 反而略增。
- **不能用滚动 365 天**：中国移动每年 6 月和 9 月各派一次，2025-09-01 那笔离窗口起点差两天被排除，当年 9 月那笔又还没发，结果拿「一笔」比上期「两笔」，凭空得出 -54%。按财报年度归集后是 +0.7%。

分红数据慢且一年只变几次，所以只在日报拉取，缓存在 `data/dividends.json`（7 天）。

## 心跳与备份

监控的沉默是有歧义的：可能今天真没信号，也可能机器已经挂了。心跳每天固定说一句话来消除这个歧义——**收不到它，就说明监控本身出事了**。

```bash
python -m src.main --heartbeat --dry-run
```

同一条命令会把 `data/alert_state.json` 与 `data/trades.csv` 快照到 `data/backups/<日期>/`，保留 30 天。这两个文件是唯一无法重新算出来的记录。

巡检的退出码也已修正：**只要有标的抓取失败就返回非 0**，不再因为碰巧有别的提醒发出去就报成功。

## 做 T：已关闭

`swing_t.enabled: false`。代码路径保留，只为让历史机动仓账本仍可读。

关闭的理由是回测数据本身：

| 策略 | 平均年化差额 | 赢过定投 |
|---|---:|---:|
| 无脑定投 | +0.00% | — |
| 做T(-5%/+5%) | **-2.82%** | 4/13 |
| 做T(-8%/+8%) | **-2.91%** | 2/13 |

之前的做法是「挑出赢的那两只」，但看具体参数就会发现问题：

| | 做T(-8%/+8%) | 做T(-5%/+5%) | 样本 |
|---|---:|---:|---:|
| 招商银行 | +0.37% | +0.95% | 12.3 年 |
| 中国移动 | +4.32% | +1.39% | 4.6 年 |

**两只对参数的偏好是相反的**（招行偏好 -5%，移动偏好 -8%），差距还有 2-3 倍。如果做 T 真的捕捉到了「低成长震荡股」的规律，它们该在同一组参数上都好。它们不一致，说明这几个「赢」是负期望分布的右尾，是因为它们赢了才被挑中——典型的样本内过拟合，没有理由相信会在未来复现。

### 记录实际行为

成交后记录一笔，日报才能算出真实持仓与浮盈：

```bash
python -m src.main --record-trade BUY 600036 100 42.35 --market cn
python -m src.main --record-trade SELL TSLA 5 315.20 --market us
```

记录保存在本地 `data/trades.csv`，不会提交到 Git。数量和成交价必须填真实值；当前版本不会替你下单。

流水会回放成真实持仓：日报里的**持仓与成本**卡片显示每只的数量、平均成本、现价和浮盈。卖出按平均成本扣减，已实现盈亏与剩余成本分开记。

## 日报

收盘后一条，覆盖全市场。行情摘要的价值不是指导当天操作（那是盘中提醒的事），是让你对持仓**保持感知**——谁强谁弱、谁在异常波动、自己成本在哪。这和盘中提醒不冲突。

包含：完整行情表（按主题分组、含近一年走势图）、**股息率**、**持仓与成本**。

```bash
python -m src.main --report daily --dry-run     # 预览
python -m src.main --report daily               # 正式发送（16:10 一条，覆盖全市场）
python -m src.main --report weekly              # 周报
python -m src.main --report monthly             # 月报
```

原先按市场拆成 A 股 16:10、美股次日 6:30 两条，已合并为一条（16:10）。

「待确认行动」卡片只在**真的有待确认事项**时才出现。它原先无条件发送，而唯一产生待确认项的做 T 已关闭，等于每天推一张写着「无需操作」的卡。

## 阿里云部署

首次安装（在服务器上）：

```bash
sudo apt update && sudo apt install -y python3 python3-venv git   # Ubuntu
git clone <你的仓库地址> ~/a_share_ma_monitor
cd ~/a_share_ma_monitor
chmod +x scripts/*.sh
./scripts/install_aliyun.sh
nano .env                 # FEISHU_WEBHOOK_URL
nano watchlist.yaml
./scripts/run_once.sh --notify-test
./scripts/run_once.sh --dry-run
```

之后每次改完代码，在**本地**一条命令同步（跑测试 → rsync → 重装 crontab → 远端试跑 → 心跳自检）：

```bash
./scripts/deploy_aliyun.sh
```

它不会覆盖服务器上的 `.env` 和 `data/`——前者存着飞书 webhook，后者存着机动仓账本与成交流水，都是本地没有且算不回来的。

若报「TCP 22 能通但握手即断」（`kex_exchange_identification: Connection closed`），那是 sshd 限流或机器资源耗尽，**本地重试无用**，需要去阿里云控制台看 VNC 或重启。

日志：`data/cron.log`；去重状态：`data/alert_state.json`；状态快照：`data/backups/`。

定时安排（`scripts/install_aliyun.sh` 自动写入）：

| 时间（北京） | 任务 |
|---|---|
| 工作日 9:35、10-11 与 13-14 每 15 分钟、14:50、15:05 | A 股盘中巡检 |
| 工作日 22:00-03:30 每 30 分钟 | 美股盘中巡检 |

开盘前那一跑已经去掉——9:00 拿到的还是昨收，纯属白跑。14:50 是新增的，那是你当天还能下单的最后决策窗口。
